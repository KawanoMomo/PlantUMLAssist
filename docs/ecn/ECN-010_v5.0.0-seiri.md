# ECN-010: v5.0.0 整理の版 — 中核の経路の外の機能を外し、保存先に .puml だけを書く

- **ステータス**: 適用済
- **種別**: 改善(機能の削除と振る舞いの変更)
- **バージョン**: v5.0.0(v4.0 `05d50f5` 〜 v5.0.0 `a895dbf`。続きの 26bf3f3 を含む)
- **対象コミット**: 下の「対策」の表のマージコミット
- **影響ファイル**: `plantuml-assist.html`, `src/app.js`, `src/core/*`(外したモジュールは各票の行), `src/ui/*`, `src/modules/*`, `server.py`, `docs/api.md`, `README.md`, `tools/`, `package.json`, `tests/`(unit・e2e)
- **関連 ADR**: ドラフト `docs/adr/drafts/v5-seiri-core-path.md`(整理の線引き)、`folder-state-outside-save-dir.md`(保存先の控えの置き場)、`screen-terms-source.md`(画面の語)

## コンテキスト

v4.0 までに、ペルソナの業務の周辺(会議・引き継ぎ・納品・レビュー・図をまたぐ監査・部品ごとの資料化)が製品に足され、
画面の入口が重なり、保存先(利用者の Git 作業木)に `.puml` 以外の控えが書かれ、保存を止める・逸らす窓が直しの流れを遮っていた。
v5.0 は「整理の版」とし、機能台帳の全行を整理表 `docs/spec/feature-triage.md` で 残す 73 / 統合 22 / 消す 78 に分け、消す・統合の行を束の票で外した。
線引き(中核の経路・保存先には .puml だけ・保存を止める / 逸らす仕組みを外す・監査 / レビュー / 部品の仕組みを外す・守りは消さない)は ADR ドラフト `v5-seiri-core-path.md`。

## 結果

- 整理表の消す・統合の行の「未」は 0(`tests/roadmap-20261115-2114-1-feature-triage.test.js` が「済」の行の痕跡の語 0 件を見張る)
- Export ▾ は 1 枚の図の SVG / PNG / 透過 PNG / クリップボードの 4 項目、ツール ▾ は 1 段の一覧、新しい図の入口はタブ列の ＋ とフォルダの右クリック「新しい図」
- 保存先に製品が書くのは `.puml` と、利用者が押した書き出しの画像だけ
- 外した機能ごとに unit・e2e を同じ票で外し、残した機能の scenario(ペルソナ台本の手順)は全員完走で v5.0.0 を出した
- CHANGELOG の外した行がこの ECN か ADR ドラフトから辿れることは `tests/reviewer-20261116-0140-seiri-trace.test.js` が見張る

## 教訓

- 機能は 1 人の 1 場面のために足すと、入口と控えが図の外に溜まる。足す前に「中核の経路のどこを進めるか」と「既存で賄えないか」を書く(願望の軸)
- 外すときは隠さず、入口・コード・試験・文書を同じ票で外し、痕跡の語を grep で 0 件にして確かめる。隠しただけの機能は退行を誰も見ない
- 利用者の手元に残った前の版の控えは移行も削除もせず、読まないだけにすると、開く・保存の守りを壊さずに済む
- 振る舞いを変えたら ECN とドラフト ADR をその票の中で書く。後から束ねると、どの変更がどの判断によるかを票とコミットから拾い直すことになる
