- **ステータス**: 適用済(v7.0 の必須 1〜5 まで。v7.0.0 以後の振る舞いの変更は `ECN-012_v7.0.0-to-v8.0-behavior.md` に足す)

- **バージョン**: v5.1.0 〜 v7.0(v5.0.0 `a895dbf` の後。ECN-010 の続き)

- **影響ファイル**: `plantuml-assist.html`, `src/app.js`, `src/core/*`(folder-impact・command-palette・workspace・file-tree ほか各票の行), `src/ui/*`, `src/modules/*`, `server.py`, `docs/spec/product-spec.md`, `README.md`, `tests/`(unit・e2e・scenarios)

## コンテキスト

v5.0.0 は「整理の版」として周辺の機能を外し、残した機能を製品仕様書 `docs/spec/product-spec.md` にまとめた(ECN-010)。
その後、v6.0 は保存先のフォルダの木(サブフォルダ)を FILES で扱う版、v7.0 はその木の中で 1 件の変更(設計変更・レビュー指摘)を
木のどこの図にも取りこぼさず反映し、作業木に余計な物を残さずに渡す版として進めた(`loop/roadmap/v6.0.md`・`v7.0.md` は製品の外)。
この間の振る舞いの変更は票ごとに CHANGELOG に 1 行ずつ書いたが、どの判断によるかを票とコミットから辿る ECN が無く、
レビューで「ADR / ECN の欠け」(複数クラスに一括適用の削除・Alt+↑/↓ の塊移動・属性の追加を塊の末尾へ・下端の改行と文字コード・一括書き出し・Esc 系)として挙がっていた。

## 結果

- 製品仕様書は v7.0。前書きに必須 1〜4 を「1 件の変更を反映して渡す順」に並べ、各行が指す scenario は `tests/roadmap-20261115-2114-3-product-spec.test.js` が実在と欄の揃いを見張る
- サブフォルダの図は FILES・Ctrl+P・書き出し・⇄ 一括置換で直下の図と同じに扱い、同じ名前の図はフォルダの道で見分ける(保存フォルダの一覧・最近開いた図は直下の図だけ)
- この ECN と ADR ドラフトが在ることは同じ unit が見張る

## 教訓

- 図の見分けを名前だけで持つと、フォルダの木へ広げた時点で「押していない図が変わる・当てたはずの図が外れる」が起きる。広げる前に、図をどの鍵で見分けるかを決めて ADR ドラフトに書く
- 戻せる操作は、戻すための前の中身の置き場を先に決める。保存先に置けないなら画面の中に持ち、戻せる範囲(直前の 1 回・後から直されていない図)を画面で言う
- 振る舞いを変える票は、その票の中で ECN の行と ADR ドラフトを書く。版の終わりに束ねると、レビューの「欠け」の指摘が何 tick も続く
