## 結果

- 製品仕様書は v8.0。前書きに必須 1〜4 を「図を続けて直して渡す順」に並べ、「製品の約束」に操作と描き直しの順の約束(操作は今の本文に働く)を 1 行足した。各行が指す scenario は `tests/roadmap-20261115-2114-3-product-spec.test.js` が実在と欄の揃いを見張る
- 続けて打つ手は、描き直しが 1.5 秒遅れても今の本文に 1 手ずつ入る(`tests/scenarios/roadmap-20261123-0857-1.spec.js` 48 本・`primary-4-s1`・`roadmap-20261123-0857-2`・`roadmap-20261123-0226-1`)
- この ECN と ADR ドラフトが在ることは同じ unit が見張る

## 教訓

- 本文を書き換えた後の後始末(読み直し・右パネルの組み直し・選択)を描き直しの後に置くと、描き直しより速い手が古い読みに対して働く。穴は入口の数だけ別々に出るので、2 回目が出た時点で共通部に寄せる
- 経路ごとの直し(別名を今の本文から数える)は 2 回で同じ穴を 2 度塞いだ。共通部に寄せた後も呼ぶ所が多い直しは、呼ぶ所の数を ADR ドラフトに書いて次の入口で漏れないようにする
- 「待つ」ことが要る所(書き出し)は、待つ旨を画面で言い、待つ間に前提(タブ・本文)が替わったら書かずに理由を言う。黙って何もしない、を残さない
