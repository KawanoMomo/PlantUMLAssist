# (ドラフト・未採番) 書き出しの大きさは本文に書かず、書き出しの入口で決めて道具の設定に覚える

- 状態: 提案 (TICKET-junior-20261123-1142-wish。roadmap v9.0 必須 1「PNG が貼って読める大きさで出る」。採番は人間)
- 日付: 2026-11-24

## 文脈
PNG は SVG の width・height と同じ画素数(1 倍)の canvas に描いていた(1 枚ずつの svgToCanvas、まとめての
`_svgTextToPngBlob`)。台本の図は幅 109〜303 px で、設計書の本文幅に広げると字がぼけ、大きさを決める所は画面に無かった。
手書きなら本文に `scale 2` か `skinparam dpi 150` を足すが、それは書き出しのために本文と Git の差分を変える。

## 決定
- PNG の画素数は SVG の寸法 × 倍率。倍率は 1〜4 倍で、何も選ばなければ 2 倍。SVG の width・height を画素数に替えて
  SVG から描き直す(1 倍の絵を引き伸ばさない)。判定と記憶は `src/core/png-scale.js`(MA.pngScale)、描くのは
  `src/app.js` の `_rasterSvgEl` の 1 本で、Export ▾ の PNG・透過 PNG、保存先の一覧のまとめての書き出し、クリップボードが通る。
- 倍率を替える所は Export ▾ の項目の下の「PNG の大きさ:」の行の 1 か所。道具(ブラウザの `localStorage` の `pua.png-scale`)に
  1 つだけ覚える。図ごと・形式ごと・保存先ごとに分けない(束の図の字の大きさを揃える)。保存先と本文には書かない。
- 本文の `scale` はその図の SVG の寸法として今どおり効き、倍率はその上に掛かる。SVG の書き出しは倍率に依らず同じバイト列。
- ブラウザが描ける上限(一辺 16384 px・面積 16384²)を超える画素数は描かずに止め、画素数と直し方を下端に言う。
  描いた canvas が頼んだ画素数でなければ書かない(空・欠けた PNG を知らせ無しに書かない)。

## 選ばなかった案
- 本文に `scale` / `skinparam dpi` を書き足す入口(図の設定): 書き出しのためだけに本文と Git の差分が動き、「GUI の 1 操作は
  名指しした要素だけを変える」に反する。
- 幅の px 指定・図ごと・形式ごとの記憶: 束の図で字の大きさが揃わず、覚える値が増える。
- PlantUML に大きい PNG を描かせる(`-tpng` と `-Sdpi`): server と jar の往復が書き出しのたびに増え、SVG と別の描画になり、
  透過・白地・待ちの道を二重に持つことになる。

## 結果
- 既定の PNG の画素数が 2 倍になる。PNG の寸法を SVG どおりと確かめていた scenario(junior-3-s4・primary-2-s4・
  primary-3-s4・primary-5-s4)は期待を「SVG の寸法 × 倍率」に直した(spec は消していない)。
- 別のブラウザ・別の PC では倍率の記憶は付いてこない(既定の 2 倍に戻る)。
