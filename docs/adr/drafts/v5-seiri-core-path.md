# (ドラフト・未採番) v5.0 整理の版: 中核の経路だけを残し、保存先に .puml だけを書く

- 状態: 提案 (TICKET-reviewer-20261116-0140。採番は人間)
- 日付: 2026-11-22
- 関連: 整理表 `docs/spec/feature-triage.md`、製品仕様書 `docs/spec/product-spec.md`、ECN `docs/ecn/ECN-010_v5.0.0-seiri.md`、
  ADR ドラフト `folder-state-outside-save-dir.md`(保存先の控えの置き場)・`screen-terms-source.md`(画面の語)

## 文脈
v4.0 までの旧ループは、ペルソナの業務の周辺(会議・引き継ぎ・納品・レビューの指摘・図をまたぐ監査・部品ごとの資料化)を製品の中に足し続けた。
v4.0 の機能台帳は 160 行・19 節、画面には台帳に無い道具も残り、同じ操作の入口が 3〜4 か所に重なっていた。
保存先(利用者の Git 作業木であることが多い)には `.puml` のほかに控え・台帳・zip が書かれ、保存を止める窓や `{名前}-編集中` への逸らしが
「押した要素だけを直して保存する」という製品の価値を邪魔していた。手書き(エディタ + plantuml.jar)と比べて増えたのは、利用者が頼んでいない物だった。

## 決定
v5.0 は「整理の版」とし、製品を次の **中核の経路** に絞る: 1 枚の `.puml` を開く → 図で押した要素だけを本文の最小の差分として直す → 描く → 保存する → 書き出す。
1. **中核だけを残す**: 開く(Import ▾・保存先の一覧・FILES)・直す(6 図種の右パネル・末尾に追加・⇄ 一括置換)・描く(同梱の plantuml.jar)・保存(Ctrl+S・自動保存・Undo)・書き出す(Export ▾ の SVG / PNG / 透過 PNG / クリップボード の 4 項目)。
   ディレクトリを扱う UI(FILES ツリー・読むだけ節・保存先の一覧・GIT 節)は骨格だけ残し、生えた枝を外す。
2. **保存先には `.puml` だけを書く**: 利用者が名前を付けた `.puml` と、利用者が押した書き出しの画像だけ。図種・最後の保存・版の控えは設定の置き場へ(`folder-state-outside-save-dir.md`)。
3. **保存を止める・逸らす仕組みを外す**: 上書きの確かめの窓・「書く前に確認 / 元ファイル保護」・`{名前}-編集中` への逸らし・保存前の監査の止め。保存は Ctrl+S と自動保存でそのファイルに書く。
4. **監査・レビュー・部品の仕組みを外す**: (a) 図をまたぐ監査・分析(突合ボード・系統チェック・影響を見る・依存グラフ) (b) 人の間のやりとり(レビュー指摘・会議・引き継ぎ・納品・資料化・提出前チェック)
   (c)「部品」「系統」を前提にした仕組み(部品フォルダ・定石構成・他の図から取り込む) (d) 入口の重なり(同じ操作の 2 つ目以降の入口)。
5. **守りは消さない**: 保存・自動保存・Undo / Redo・既存の `.puml` を壊さず開く・保存すると大きく消える形の警告と「前回保存版に戻す」・この図の履歴。
6. **外した機能の残り物は読まず書かず消さない**: 保存先や localStorage に前の版が残した控え(`_vault/`・`_meetings.json`・`_export-log.json`・`_sets/`・`_svg-verify.json`・`指摘.md`・`' @pin` 行など)は
   製品が読まなくなるだけで、消さない・動かさない。それらが残る保存先も今までどおり開けて描け、無変更の保存はバイト一致。
7. 外すときは入口・コード・設定・unit・e2e・`tools/`・文書の記述を同じ票で外す(隠して残さない)。行ごとの判定と根拠は整理表 `docs/spec/feature-triage.md` が正本(残す 73 / 統合 22 / 消す 78)。

## 選ばなかった案
- **設定で隠す(既定で非表示)**: コードと試験と入口の重なりが残り、隠した機能の退行を誰も見ない。整理の目的(画面だけで分かる・入口は 1 つ)を果たさない。
- **プラグインとして切り出す**: 単一 HTML + `src/` でビルドの無い構成に読み込みの仕組みを足すことになり、v5.0 の範囲を超える。外した機能は git の履歴から戻せる。
- **保存先に `.gitignore` を書いて控えを隠す**: 利用者のファイルを増やす点で同じ。
- **外した機能の残り物を移行・削除する**: 利用者のファイルに製品が手を出すことになる。読まないだけにした。

## 結果
- 画面のボタン・窓・Ctrl+K の行・server.py の API が減り、同じ操作の入口は 1 つになった。製品仕様書 `docs/spec/product-spec.md` が残した機能の全部(96 行)を場面ごとに書く。
- 外した機能を使っていた利用者は、その操作を手書きか別の道具で行う(例: レビュー指摘は Git のレビュー、資料化は書き出した画像を貼る)。
- 外した機能の一覧と、それぞれのマージは ECN `docs/ecn/ECN-010_v5.0.0-seiri.md`。
- unit が整理表の行数・判定・「済」の行の痕跡 0 件(`tests/roadmap-20261115-2114-1-feature-triage.test.js`)と、
  CHANGELOG の外した行が ECN かこのドラフトから辿れること(`tests/reviewer-20261116-0140-seiri-trace.test.js`)を見張る。
