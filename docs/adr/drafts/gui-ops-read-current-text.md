# (ドラフト・未採番) GUI の操作は描き直しの結果でなく今の本文を読む

- 状態: 提案 (TICKET-roadmap-20261123-0857-3 / roadmap v8.0 必須 5。採番は人間)
- 日付: 2026-11-23
- 束ねるドラフト: `props-rebuild-on-update.md`(必須 2)・`selection-carry-by-line.md`(必須 1)。振る舞いの変更と票・マージは `docs/ecn/ECN-012_v7.0.0-to-v8.0-behavior.md`

## 文脈
本文を書き換えた後、読み直し・右パネルの組み直し・選択の付け直しは、描き直し(`refresh` → `POST /render` → overlay)の後に起きていた。
描き直しの待ちは ⚙ の描画の待ちで 1 秒まで延び、遅い PC ではさらに延びる。その間に打った次の手は、古い parse 結果・前に組んだ右パネル・プレビューに在る絵を読んで働いた。
同じ穴が入口ごとに別々に出た: 続けて足した別名の重なり(TICKET-junior-20261123-0742・TICKET-owner-20261123-0842-1。どちらも data-loss で、経路ごとに 2 度塞いだ)、
確定の直後に選んだ To が後の組み直しで消える空振り(TICKET-releaser-20261123-0142-4。製品を変えず scenario の待ちで避けていた)、
描き直しの前に押した書き出しが黙って何もしない・直前の絵を書く(TICKET-roadmap-20261123-0857-2)、反映のたびに選択が外れる(TICKET-primary-20261123-0810-wish)、
木へ当てた置換を戻す手が開いている図と開いていない図で割れる(TICKET-owner-20261123-0742-1)。

## 決定
GUI の手は、押した時点の本文(とその同期の読み)を読んで働く。描き直しの結果(プレビューの絵・overlay・前に組んだ右パネル)は見せるためのもので、手の入力にしない。
入口ごとでなく、本文を書き換える口・選択・書き出し・戻しの共通部で守る。

共通部に寄せた所:
- **書き換えの後始末** `src/core/props-rebuild.js`(MA.propsRebuild): 右パネルの ctx の `setMmdText` は本文を入れて同期で読み直し、`onUpdate` は右パネルをその場で今の読みから組み直してから描き直しを予約する。後から来る refresh は控えと同じ本文・選択・図種なら組み直さない。図の行間の「＋ ここに挿入」・帯の内外の挿入・Delete キー・状態表の遷移追加の窓も同じ口(`src/app.js` の `_editCtx`)
- **選択** `src/core/selection-carry.js`(MA.selectionCarry): 反映の前の本文・選択を控え、組み直す前に選んでいた行を本文の差分で新しい本文の行へ辿って同じ種類の要素を選び直す。辿れなければ選ばない
- **書き出し** `src/core/export-wait.js`(MA.exportWait): プレビューの絵が押した図の今の本文の図かを控え(`_previewPic`)と比べ、違えば待つ旨を下端に言って描き直しを待ち、届いたら 1 回だけ書く。Export ▾・FILES の右クリック・Ctrl+K・Ctrl+Shift+S は exportSVG / exportPNG の 1 本を通る
- **置換の戻し** `src/core/rename-undo.js`(MA.renameUndo): 戻す図は押した時点の各図の本文で決める(置換の直後のままの図だけ。先に Ctrl+Z で戻した図・後から書き換わった図は戻さない)。戻すための前後は画面の中に持つ
- **別名の数え方** `src/core/id-normalizer.js` の `normalize`: 今の本文に語として出る別名も使用中として避ける

## 寄せられなかった所(経路ごとのまま・描き直しの結果を読むまま)
- 別名の数え方は共通部が 1 つでも、今の本文を渡すのは呼ぶ側(追加フォーム 13 か所と 4 図種の addBulk)。新しい追加の入口を足すときは同じ形で本文を渡す
- 選択の持ち越しは右パネルの反映だけ。図の行間の挿入・Delete キーでは持ち越さない(書き換えた側が選択を自分で替える)
- 選んだ要素の右パネルは書き換えの直後の 1 回だけ組み直しを省き、それ以外は描き直しの後に組み直す(手続きの展開など本文の外の答えを待つ欄があるため)。本文欄で打った・Undo で本文が替わったときも描き直しの後に組み直す
- 図を押す手(overlay のクリック)は見えている絵を読む。描き直しが届く前の図を押したときは、見えている要素以外を選ばない(`_noteStaleOverlayClick`)。押した要素を今の本文の行に結ぶのは選択の側
- 描けた SVG に合わせて図種を替える `_svgKindFix`(アクターだけの白紙のユースケース図がシーケンス図に描かれる)は描き直しの結果を読む。v8.0 の範囲の外として残した
- 透過 PNG の書き出しは PNG と同じ道(exportPNG)で、待ちの個別の scenario は無い

## 選ばなかった案
- 入口ごとに今の本文から数え直す: 2 度塞いだが、挿入・反映・削除・書き出しと次の入口で同じ穴が出た
- 描き直しが届くまで手を止める・待たせる表示や設定を出す: 新しい設定・窓を足さない(roadmap v8.0)。遅い PC で手が止まる
- 描き直しの待ちを 0 にする: 描き直しの要求が手の数だけ飛び、描画の待ちの設定の意味が無くなる。書き出しの穴(絵が届く前)は残る

## 結果
- 描き直しが 1.5 秒遅れても、続けて打つ手は今の本文に 1 手ずつ入り、1 手ずつ戻る(`tests/scenarios/roadmap-20261123-0857-1.spec.js`・`primary-4-s1.spec.js`・`roadmap-20261123-0857-2.spec.js`・`roadmap-20261123-0226-1.spec.js`)
- 製品仕様書の「製品の約束」に「操作は今の本文に働く」を置いた。新しい入口はこの約束と上の共通部を通す
