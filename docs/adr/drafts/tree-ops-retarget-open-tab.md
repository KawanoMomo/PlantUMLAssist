# (ドラフト・未採番) FILES の右クリックで図を移す・名前を変えるとき、開いているタブは書くのを止めてから付け替える

- 状態: 提案 (TICKET-roadmap-20261122-0855-3。roadmap v6.0 必須 4「ツリーの右クリックでフォルダの中を整える」。採番は人間)
- 日付: 2026-11-22
- 前提: `subfolder-doc-place.md` (タブが居場所 `dir` / `sub` を持つ)

## 文脈
移動・名前変更はディスクの付け替え (server の `POST /file-op`) と、その図を開いているタブの付け替え (名前・居場所・前回保存版の基準) の 2 つからなる。
タブは自動保存 (debounce) と Ctrl+S で書き先を「その時点のタブの名前と居場所」で決める。付け替えの前後に書きが割り込むと、
(a) debounce 中の書きが付け替えの後に前の場所へ届き、前の場所にファイルが作り直されて 2 枚になる、(b) 付け替えの途中で前の名前へ書く。

## 決定
- 付け替えの手前で `autoSave.settle()` を待ち、待っている書きを前の場所へ書き切らせる (付け替えで一緒に運ばれる)。
- 次に、そのタブの書きを止める (`MA.holdDocWrites(id, true)`)。止めている間は自動保存・タブの書き戻し・Ctrl+S のどれもそのタブを書かない。
- ディスクの付け替えが成功したら、タブの名前と居場所を新しい場所へ移し (`MA.retargetDoc` → `workspace.setPlace` / `rename`)、前回保存版の基準も新しい鍵へ移す。
  未保存の本文はタブに残す。失敗したらタブは前のまま。最後に止めを外す。
- 行き先は保存先とその下のフォルダ (FILES のツリーに出ているもの) から選ぶ。保存先そのものへ移した図は「今の保存先に従う直下の図」に戻す。
- 削除は server が消す直前の中身を版として控える (上書きの無かった図でも「この図の履歴」から戻せる)。
- 「新しいフォルダ」は `file-op` の `mkdir` で 1 つだけ作る (中に控え・印・設定を置かない。同じ名前は 409)。

## 却下した案
- 付け替え後に前の場所に出来たファイルを消す: 利用者の別の図を消す恐れがあり、「押した対象だけが変わる」に反する。
- 移動・名前変更をタブの保存の口に寄せる (新しい名前で保存してから前のファイルを消す): 未保存の行がディスクに書かれてしまい、「未保存の行はタブに残る」と食い違う。
