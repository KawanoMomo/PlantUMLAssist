# (ドラフト・未採番) 保存先を決めていない間は、保存先の一覧に図を並べない

- 状態: 提案 (TICKET-owner-20261123-1922-1。採番は人間)
- 日付: 2026-11-23
- 関係するドラフト: `save-dir-ownership-v6.md`(保存先は利用者が開いたフォルダとその下)

## 文脈
保存先を決めていない既定の画面 (設定の backend が file でない) でも、FILES の保存先節と保存先の一覧は
設定に残る既定のフォルダ `./autosave` の図を並べていた。一方で保存 (`save-target.decide`) はダウンロードで、
書き出しもダウンロード、`!include` も保存先の無い図として解いていた。一覧から開いた図を直して Ctrl+S しても一覧の図は直らず、
開き直すと直す前の図が開く。一覧に並べたフォルダと、保存・書き出し・`!include` の場所が 2 つに割れていた。

## 決定
- 一覧が読むフォルダは `save-target.listDir(cfg)` の 1 つで決め、保存の行き先 (`decide`) も同じ関数から決める。
  保存先を決めていない (backend が file でない) ときは '' で、一覧も FILES の保存先節も図を並べない。
- 並べない代わりに、その場所で「保存先のフォルダを決めていません。保存と書き出しはブラウザのダウンロードになります。」と、
  決める入口の語「保存先のフォルダを選ぶ…」を出す (新しいボタン・設定は足さない)。
- 保存先を決めた画面の振る舞い (上書き保存・図と同じフォルダへの書き出し・`!include`) は変えない。

## 却下した案
- 並べたフォルダ (`./autosave`) を保存先として扱う: 利用者が選んでいないフォルダ (製品のチェックアウトや設定の置き場の下) に
  黙って `.puml` を書くことになり、「保存先は利用者が開いたフォルダ」(`save-dir-ownership-v6.md`) に反する。
- 並べたまま、行に「保存はダウンロード」の印を付ける: 一覧から開いて直した図が一覧の図に入らない形そのものは残る。

## 影響
- 保存先を決めていない人が既定のフォルダに置いた図は、「保存先のフォルダを選ぶ…」でそのフォルダを選べば並ぶ。
