# (ドラフト・未採番) 反映の後の選択は、本文の差分で辿った行で持ち越す

- 状態: 提案 (TICKET-primary-20261123-0810-wish / roadmap v8.0 必須 1。採番は人間)
- 日付: 2026-11-23

## 文脈
選択は `{ type, id, line }` で持つ。id は図種と要素で作り方が違い、部品・クラス・状態は名前、
関係は並びの番号 (`__r_2`)。右パネルの「変更を反映」で名前 (識別子) を直すと id が parse 結果から消え、
`propsRenderer` が何も描かないので前のフォーム (古い要素に結んだ手) が右パネルに残った。
行の増減で番号の id がずれると、選択は同じ id の別の要素を指した。図種ごとに選び直しの手を足すと、
入口が増えるたびに同じ穴が別々に出る (roadmap v8.0「前メジャーとの違い」)。

## 決定
- 右パネルの ctx.setMmdText が書き換える直前の本文・parse 結果・選択を控え、`refresh()` が右パネルを組み直す前に
  `MA.selectionCarry.carry()` で選択を持ち越す。書き換えた側が選択を自分で替えた (削除で外した・動かした先を選んだ)
  ときは控えと違うので触らない。
- 持ち越しは「選んでいた要素の行」を本文の差分で新しい本文の行に辿る (`mapLine`)。書き換えた塊の外はずれた分だけ動かし、
  塊の中は同じ中身の行が 1 つだけならそこ (並べ替え・字下げを変えた移動)、塊の行数が同じなら同じ位置、
  行数が違えば塊の先頭の行だけを辿る。
- 辿った行で、選んでいた要素と同じ parse 一覧 (elements / relations / transitions …) の要素を選ぶ。kind が選択の種類
  そのもの (message 等) なら同じ kind に限る。辿れない・同じ種類の要素が無いときは選ばない。
- parse 一覧に無い種類の選択 (クラスのメンバー・本文の行・文書の飾り) と複数選択はそのまま。

## 選ばなかった案
- 図種モジュールごとに反映の手の後で選び直す: 6 図種 × 入口の数だけ同じ手が要り、次の入口で再発する。
- 描き直しの後の選択枠 (overlay) で同じ行の枠を選び直す: 描き直しが届くまで (遅い PC で数秒) 古いフォームが残る。
- id を行番号から作り直す: 既存の parse・overlay・unit の契約 (DiagramModule) を全部変える。

## 結果
- 名前を直した後も同じ行の要素の右パネルが組み直される。番号の id がずれても動いた先の同じ要素を追う。
- 行が消えた・塊の途中の行は選択を外す (押していない要素に次の反映・Delete を効かせない)。
