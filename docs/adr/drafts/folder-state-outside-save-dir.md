# (ドラフト・未採番) 保存先ごとの控えを保存先の外に置く

- 状態: 提案 (TICKET-owner-20261115-1827-1。採番は人間)
- 日付: 2026-11-15

## 文脈
保存先は利用者の Git 作業木であることが多い。server は保存のたびに保存先へ `_kinds.json`(保存したときの図種)・
`_meta.json`(最後の保存)・`_versions/`(上書き前の版の控え。自動保存・Undo・Redo のたびに増える)を書いていたので、
利用者は毎回 `git status` の未追跡を片付けるか `.gitignore` を書く必要があった。手書き (エディタ + plantuml.jar) なら .puml しか増えない。

## 決定
- 保存先に書くのは利用者が名前を付けた `.puml` と、利用者が押した書き出し (SVG / PNG) だけ。
- 上の 3 つの控えは設定の置き場 `DATA_ROOT/folders/<保存先の絶対パスの sha1 先頭 16 桁>/` に持つ
  (`server.py` の `folder_state_dir`。試験は `PUA_DATA_ROOT` で test-results/ の下)。
- 保存先に前からある控えは読むだけ: 版の一覧・本文・図種・最後の保存はそちらも見る。足さない・捨てない・動かさない。
  上限で捨てる版は新しい置き場の版だけから選ぶ。「図を全部消す」(利用者が押す片付け) だけは今までどおり両方を消す。

## 選ばなかった案
- 保存先に `.gitignore` を書く: 利用者のファイルを増やす点で同じ。
- 控えをやめる: 「この図の履歴」と図種の取り違え防止 (BLK-junior-20260912-2103) が失われる。

## 結果
- 保存先を別の PC に移すと、控え (版の履歴) は付いてこない (Git の履歴が正本)。
- `_roles.json` `_tickets/` などほかの控えは、その機能を使ったときだけ保存先に書く (この決定の範囲外。整理の棚卸しで扱う)。
