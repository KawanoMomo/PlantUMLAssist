# (ドラフト・未採番) 右パネルの語の正本を src/ui/terms.js に置く

- 状態: 提案 (TICKET-roadmap-20261115-2114-4。採番は人間)
- 日付: 2026-11-22

## 文脈
右パネルの欄名・ボタンの語は 6 図種のモジュール (`src/modules/*.js`) がそれぞれ文字列で書いていた。
同じ役の欄が図種ごとに「Alias (id)」「名前 (id)」「Alias」、「Label」「ラベル」「表示名」、「更新」「変更を反映」、
「✕ 削除」「クラスを削除」「削除 / Delete」と分かれ、英語の併記(「矢印の種類 / Arrow」)と実装の説明
(「ライフライン推論 (activate/deactivate)」)が混ざっていた。製品仕様書 `docs/spec/product-spec.md` は語を決めていなかった。

## 決定
- 同じ役の欄・ボタンの語は `src/ui/terms.js` の `window.MA.terms` に 1 つだけ置き、6 図種のモジュールはそこから読む。
  HTML は `properties.js` より先に読む。node の unit で `properties.js` を require したときは、同じ window に語が無ければ
  `properties.js` が `terms.js` を読む。
- 製品仕様書の「読み方 → 画面の語」の表が語の一覧で、`terms.js` と同じ値を持つ。unit
  `tests/roadmap-20261115-2114-4-terms.test.js` が表・`terms.js`・6 図種の右パネルの描画を突き合わせる。
- 仕様書の「入口」で「」に囲んだ語は画面にそのまま出る語とし、同じ unit が画面の元 (HTML と `src/`) に実在することを確かめる。
- 日本語と英語は併記しない。PlantUML の記法 (`activate` 等) は記法として添えてよい。

## 選ばなかった案
- 語を各モジュールの文字列のまま残し、unit で揃っていることだけを確かめる: 次に欄を足す人が正本を探せない。
- `properties.js` の中に語を持つ: 部品の関数と語が 1 ファイルに混ざり、語だけを見直しにくい。

## 結果
- 図に出る文字の欄は、参加者は「表示名」、メッセージ・注釈は「本文」のまま (シーケンスの本文の欄の語は別票)。
- 関係の種類のカード (「関連 / association」など) は記法の添え書きなので、この決定の範囲外。
