# (ドラフト・未採番) 保存先から開いた図の書き出しは保存先の中へ書く

- 状態: 提案 (TICKET-primary-20261115-2240-wish。roadmap v6.0 必須 2「書き出しを保存先へ」。採番は人間)
- 日付: 2026-11-22

## 文脈
Export ▾ の SVG / PNG / PNG(透過背景)はブラウザのダウンロードで、置き場所は画面に出ず、通常の PNG と透過 PNG は
同じ名前(`{名前}.png`)だった。図を Git で管理する利用者は、書き出した画像をダウンロード先から保存先へ移し替え、
どこに何を書いたかをディスクの外から確かめていた。

## 決定
- 保存先から開いた図(自動保存の書き先がフォルダで、そのフォルダに `{名前}.puml` がある図)の 3 つの書き出しは、
  server の `POST /export-file?dir=&name=&kind=&sub=`(本文は書き出したバイト列)で保存先の中へ書く。
  名前は図の名前 + `.svg` / `.png` / `.transparent.png`。書くのは押した 1 ファイルだけ(`.puml`・控え・設定には触らない)。
- 置き場(`sub`)は既定で図と同じフォルダ。保存先の下のフォルダに替えられ、保存先ごとにブラウザの記憶
  (`localStorage` の `pua.export-sub:{保存先}`)に覚える。保存先には設定を置かない(`folder-state-outside-save-dir` と同じ考え)。
  `..`・`.` 始まり・ファイル名に使えない字の置き場は server も client も受けない。
- 書いた直後に下端と Export ▾ の行が「名前 → 置き場 · N バイト · 新規 / 上書き」を言う。
- `{名前}.puml` が保存先に無い図(Import ▾ で開いただけ・保存前の新しい図・ブラウザ内保存)は server が 404 + fallback を返し、
  今までどおりダウンロードで受ける。クリップボードとエラー中の書き出しの止め方は変えない。

## 選ばなかった案
- 名前と置き場を毎回打つ窓: 毎回の手数が増え、既定の名前で足りる回が大半。名前の欄は必須にしない。
- 既存の `POST /autosave-svg`(SVG だけ・末尾に sha1 の印を足す)を広げる: PNG を扱えず、印は書き出しの中身を変える。
- 置き場の記憶を server の設定(`DATA_ROOT`)に持つ: 1 つのブラウザの手元の好みで足り、試験の切り離しも localStorage で済む。

## 結果
- 保存先から開いた図の書き出しで download は来ない。download を前提にした primary 場面 4 の scenario と owner-0140 は
  受け取り方だけを書き直した(中身・本文・手数の期待は同じ)。
- 別のブラウザ・別の PC では置き場の記憶は付いてこない(既定の図と同じフォルダに戻る)。
