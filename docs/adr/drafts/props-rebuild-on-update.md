# (ドラフト・未採番) 右パネルの書き換えの直後に、右パネルをその場で今の本文から組み直す

- 状態: 提案 (TICKET-roadmap-20261123-0857-1 / roadmap v8.0 必須 2。採番は人間)
- 日付: 2026-11-23

## 文脈
図種モジュールは右パネルの手 (「+ 追加」「まとめて」・反映・削除など) で `ctx.setMmdText(本文)` → `ctx.onUpdate()` を呼ぶ。
以前の `onUpdate` は refresh を予約するだけで、右パネルの組み直しは描き直しの待ち (150ms〜1s) の後だった。
その間に打った次の手は、組み直し前のフォーム (閉じ込めた古い parsedData) に対して働き、
別名を古い読みで決める・始点 / 終点の候補に今足した要素が無い・確定の直後に選んだ欄が後の組み直しで空に戻る、が
入口ごとに別々に出た (TICKET-junior-20261123-0742・TICKET-owner-20261123-0842-1・TICKET-releaser-20261123-0142-4)。

## 決定
- 右パネルの ctx は共通部 `MA.propsRebuild.makeCtx` で作る (画面は `src/app.js` の renderProps の 1 か所)。
  `setMmdText` は本文を入れて同期で読み直し、`onUpdate` は右パネルをその場で今の読みから組み直してから refresh を予約する。
- その場で組み直したときの本文・選択・図種を控え (`MA.propsRebuild.tracker`)、後から来る refresh は控えと同じなら
  右パネルを組み直さない (組み直した後に利用者が選んだ・打った欄を消さない)。控えは 1 回で使い切る。
  本文欄で打った・Undo・図種が替わったなど、控えと違えば今までどおり組み直す。
- DiagramModule の契約 (`renderProps(sel, parsed, el, ctx)`、ctx の 3 つの口) は変えない。図種モジュールに手を足さない。

## 選ばなかった案
- 入口ごとに今の本文から別名・候補を数え直す: (a)(b) はそれで塞いだが、挿入・反映・削除など次の入口で同じ穴が出る。
- 描き直しが届くまで右パネルを止める・待たせる表示を出す: 新しい設定・窓を足さない (roadmap v8.0 の守り)。遅い PC で手が止まる。
- refresh の待ちを 0 にする: 描き直しの要求が手の数だけ飛び、描画の待ちの設定 (render-modes) の意味が無くなる。

## 結果
- 間を空けずに続けた手も、描き直しが 1.5 秒遅れても、打った時点の本文に対して 1 手ずつ入る。
- 1 手ごとに右パネルの組み直しが 1 回増える (同じ手の後の refresh では組み直さないので回数は今と同じ)。
