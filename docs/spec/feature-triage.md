# 整理表 — v5.0 で 残す / 統合 / 消す 機能

v5.0「整理の版」の成果物 1(TICKET-roadmap-20261115-2114-1)。機能台帳(ループの `features.md`)にある全部の行を、残す・統合・消すのどれかに分け、1 行ずつ根拠を付けた表。
対象は、v4.0 時点の台帳(160 行・19 節。旧ループから写したもの)と、その後に書き換えた・足した行。既に外した束の行も「消す・済」として載せる。
台帳に行は無いが製品の画面にある道具と、配布(`packaging/`・windows-app・「更新を確認」)・`tools/` の行は末尾の 2 節にまとめた。

## 決め方

- 線引きは `roadmap/v5.0.md` の位置づけに従う。軸は「1 枚の `.puml` を開く → 押した要素だけを直す → 保存する → 書き出す」
  - **残す**(中核 = 1 枚の図の経路): 開く・直す・描く・保存・書き出す
  - **骨格だけ残す**(ディレクトリを操作する UI): FILES ツリー・読むだけ節・保存フォルダの一覧・GIT 節。この表では「統合」と書き、残す骨格と消す枝をその行で分ける
  - **消す**: (a) 図をまたぐ監査・分析 (b) 人の間のやりとり(レビュー・指摘・会議・引き継ぎ・納品・資料化) (c)「部品」「系統」を前提にした仕組み (d) 保存を止める・逸らす仕組みと、保存先に `.puml` 以外を書くこと (e) 入口の重なり
- 束の票に「判定」節がある行はそれを写した。無い行は上の線引きで決めた
- 根拠に使うのは設計書(`design/2026-11-15-plantumlassist-v5-seiri.md`)4 章の 3 つだけ。各行の根拠はどれを使ったかを先頭の語で示す
  - **台本**: 新しい台本(`loop/personas/junior.md`・`primary.md`・`reviewer.md`)の業務に要るか
  - **設計書**: 最初の設計書(`docs/superpowers/specs/2026-04-17-plantuml-assist-design.md`)と 6 図種の設計書に根があるか
  - **価値**: 手書き + プレビューと比べて、PlantUML の GUI エディタとしての価値になるか
  - 旧ループの台本にあったこと・票が done であること・作る手間は根拠にしない
- 迷ったら消す。ただし守り(保存・自動保存・Undo・既存の `.puml` を壊さず開く)は消さない。人間由来の行(Import ▾・ファイルを開く・alt / loop の範囲選択・note の位置・GIT 節・配布)は消さない側に倒した

## 列の読み方

- **判定**: 残す / 統合 / 消す の 3 つだけ。「統合」は行の一部を残し一部を外す(残す部分と外す部分を根拠に書く)か、別の行の入口に寄せること
- **統合先**: 統合の行で、残る側の行・入口。他の行は「—」
- **束**: その行を外す票の id。票がまだ無い束は「(票なし) 束の名前」で書く。残す行は「—」
- **状態**: 消す・統合の行で、外し終えたら「済」、まだなら「未」。残す行は「—」。束の票が done でも、痕跡の語が画面か `src/` に残っていれば「未」(締めの TICKET-roadmap-20261115-2114-2 が掃く)
- **痕跡の語**: 消す・統合の行で、外したことを確かめる語(バッククォートで囲む)。その機能だけを指す画面の文言かモジュール名を選んだ。`plantuml-assist.html` と `src/` を grep して 0 件なら外れている(コメントの中の語も数える)。「済」の行の語は今 0 件
- 外した機能の名前が別の機能のコメントや CSS の注釈にだけ残っているものは、末尾の「締めへの申し送り」に書いた(機能は外れているので「済」のまま)
- この表は unit `tests/roadmap-20261115-2114-1-feature-triage.test.js` が読み、行数・判定の値・根拠の空欄・配布の行・「済」の行の痕跡 0 件を確かめる
